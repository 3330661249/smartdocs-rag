# 合成制度问答：从“能回答”到“能指出依据和缺口”

## 用户任务与案例范围

假设一位员工需要核对差旅报销规则，同时资料库里保留旧版制度、上海补充规则、资料安全与设备采购规则。用户希望快速找到**适用的版本和原文**；当问题缺少日期、地点或制度没有规定时，系统应说明无法确认。

这是一组合成资料，机构与制度均为虚构。它用于检验本仓库的产品与工程边界，不是企业上线案例，也不包含真实员工资料。当前应用仍使用配置的外部向量化与聊天模型；运行实际问答前，应确认这些合成资料可以发送给所选服务。

## 我选择检查的三个环节

1. **检索：** 是否拿到预期文件。旧版与新版并存、上海专项规则覆盖通用规则，是刻意设置的干扰。来源命中只能说明文件到了上下文，不能说明正确段落已被使用。
2. **引用：** 回答标出的编号是否映射到本次检索片段，以及预期来源是否被引用。引用编号有效也不能证明整句结论受到原文支持。
3. **决策：** 对资料缺失和条件不明确的问题，是否明确拒答。对已经回答的内容，人工依据原文填写 `reviewer_support`，程序不会自行把“有引用”写成“事实正确”。

## 可复现的最小演示

先运行无需 Key、不会调用模型的资料校验与手写记录评分：

```bash
python -m evals.policy_eval --validate-only
python -m evals.policy_eval --runs evals/policy_case/example-handwritten-not-model.jsonl
```

第二条命令使用三条**手写示例记录**：正常回答、资料缺失时拒答，以及错误地替缺少年份的问题确定住宿上限。它的覆盖率只有 3/30，输出仅演示评分规则，**不是模型效果**。

其中 A25 的手写回答给了“450 元 [1]”：编号可能对应一段真实资料，但问题允许 2025 或 2026 年行程，2026 年上海还区分 4 月前后。记录器会把这个未澄清就确定金额的行为算作失败。手写示例没有运行时的资料摘要，因此报告中的 `suite_match` 为 `null`；实际运行记录会带资料摘要，资料变化后评分会拒绝混用。

要观察真实模型行为，先按 README 配置自己的服务，再显式运行少量合成案例：

```bash
mkdir -p evals/runs
python -m evals.policy_run --live --limit 3 --output evals/runs/first-three.jsonl
python -m evals.policy_eval --runs evals/runs/first-three.jsonl
```

`evals/runs/` 需自行创建，并被 Git 忽略；也可把 `--output` 指向其他已存在的本地目录。此命令会调用外部 Embedding 和 Chat API，可能计费。默认只跑前三条；`--all` 才跑全部 30 条。输出保留案例 ID、问题、模型名、资料版本摘要、检索来源、引用来源、回答状态与耗时；不写入 API Key。中途失败会留下已完成记录并清理本次临时知识库，报告显示实际覆盖率。

若想从产品页面观察同一场景，可启动 `streamlit run app.py`，上传 `evals/policy_case/` 下的五个 `.md` 资料，依次提问 D01、N19、A25，并检查页面上的回答、引用和检索片段。记录器调用非流式问答，页面使用流式问答，两者 Prompt 与输出形态不同；实际页面结果需单独记录，不能由评测记录或手写示例推断。

人工复核时，逐条阅读回答、资料原文和问题中的 `reference_answer`，将已回答记录中的 `reviewer_support` 从 `null` 改成 `"supported"` 或 `"unsupported"`，再重新运行评分。`supported` 应以整条答案中的事实都能由所引原文支持为准；需要主观判断的条目保留 `null` 并说明分歧。当前脚本未计算调用费用，不能用耗时估算费用。

## 评测集与验收口径

30 条问题位于 [`evals/policy_case/cases.json`](../evals/policy_case/cases.json)：10 条直接回答、8 条跨来源、6 条资料缺失、6 条条件不明确。每条样例保存人工复核参考答案；可回答问题另外保存预期来源与能在合成资料中逐字找到的短证据。校验脚本会拒绝缺失、重复或与原文不一致的标签。

最终结果需要分别报告：运行覆盖数、可回答问题的来源检索命中、预期来源引用、回答状态、应拒答问题的拒答数，以及**人工复核过**的语义支持数。所有分母保留在报告中；覆盖不全时不能声称整套评测通过。样本数较小，只适用于这个合成场景的改动对照，不代表其他制度或生产环境。

这轮交付的是**资料、标注规则、记录与评分工具**。还没有真实模型运行结果、人工复核结论或某项策略改动前后的对照。下一次对照应冻结资料和问题，保留模型与向量化模型配置，只改变一个因素，例如切分方式，然后用同一套口径观察收益与失败样例。
